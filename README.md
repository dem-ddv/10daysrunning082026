# Автообновляемый дашборд 10-дневного забега

Файлы:
- `index.html` – дашборд GitHub Pages.
- `data.json` – данные, которые читает дашборд.
- `update_data.py` – скачивает Results Zone, находит пять нужных спортсменов и парсит покилометровку.
- `.github/workflows/update-results.yml` – запускает обновление примерно раз в час.

## Как выложить
1. Положить все файлы в корень репозитория, сохранив папку `.github/workflows/`.
2. GitHub → **Settings → Pages** → Deploy from a branch → `main` / `/ (root)`.
3. GitHub → **Actions** → `Update race results` → **Run workflow** для первого ручного запуска.
4. Проверить, что после запуска изменился `data.json`.

Дальше workflow запускается каждый час. GitHub может запускать cron с небольшой задержкой. Открытый дашборд проверяет свежий `data.json` каждые 5 минут, поэтому новую выгрузку подхватит без ручного reload.

Если workflow получает 403 при `git push`, в **Settings → Actions → General → Workflow permissions** выбрать **Read and write permissions**.

## Интерфейс периода и рост гонки

Период выбирается двойным дискретным ползунком по суткам. Левая ручка задаёт начало периода, правая — конец; выбранные сутки подсвечиваются между ними.

Интерфейс рассчитан на автоматический рост гонки с 5 до 10 суток: новые сутки появляются в шкале сами после обновления `data.json`. Суточные таблицы, график километража по суткам и timeline отдыха используют внутренний горизонтальный масштаб/скролл при необходимости, а непрерывные графики остаются на ширину карточки. Сглаживание ходового темпа автоматически увеличивается для длинных диапазонов.
